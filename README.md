# Vitalia Health

Repositorio académico del Proyecto APT desarrollado para la asignatura Capstone de la carrera Ingeniería en Informática de Duoc UC.

## Descripción del proyecto

Vitalia Health es una propuesta de plataforma web y móvil destinada a centralizar la gestión de exámenes médicos de manera segura y ordenada.

La solución permitirá almacenar y consultar documentos por paciente, tipo y fecha, manteniendo trazabilidad sobre los accesos y modificaciones. Además, incorporará inteligencia artificial asistiva para extraer información relevante, generar resúmenes y explicar los resultados con un lenguaje sencillo.

La inteligencia artificial tendrá un propósito informativo. No realizará diagnósticos, no prescribirá medicamentos y no reemplazará la interpretación de un profesional de la salud.

## Objetivo general

Diseñar e implementar un prototipo funcional web y móvil de Vitalia Health que permita gestionar exámenes médicos de forma centralizada y segura, incorporando extracción de información y explicaciones asistidas por inteligencia artificial para facilitar la comprensión de los resultados sin reemplazar la interpretación profesional.

## Propuesta de valor

Vitalia Health busca aportar valor mediante cuatro funciones principales:

1. Centralizar los exámenes médicos por paciente, tipo y fecha.
2. Extraer información relevante desde los documentos.
3. Explicar los resultados con palabras sencillas.
4. Facilitar una consulta más informada con el profesional de la salud.

## Tecnologías propuestas

- Flutter y Dart para la aplicación móvil.
- Node.js 20 y TypeScript para el backend.
- Express o Fastify como framework del backend.
- PostgreSQL 16 para la base de datos.
- MinIO o Amazon S3 para el almacenamiento documental.
- JWT para autenticación y autorización.
- Zod para validación de datos.
- Docker Compose para el entorno de desarrollo.
- Jest y Supertest para pruebas.
- OpenAPI o Swagger para documentación de la API.

Las alternativas tecnológicas pendientes se seleccionarán antes de cerrar la arquitectura. Cualquier cambio respecto del stack propuesto deberá responder a una limitación concreta, presentar una mejora verificable y ser validado con la cliente.
